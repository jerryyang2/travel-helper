# 旅遊小幫手：手動啟用同步

網站可直接使用本機模式。此流程不需要安裝外掛；雲端帳號、資料庫及登入郵件由網站建立者自己的 Supabase 專案提供。

目前公開網站沒有預設雲端專案，也沒有上傳任何使用者的本機旅程。完成下列設定後，使用者還需主動按「將目前旅程加入雲端」。

## 1. 建立資料表與權限

1. 在 [Supabase 官方管理介面](https://supabase.com/dashboard) 建立自己的專案，依官方畫面選擇方案與地區。帳號、付款及方案選擇請自行確認。
2. 在該專案的 SQL Editor 執行本目錄的 [schema.sql](schema.sql)。也可從 App「同步與分享」下載同一份設定。
3. 確認執行完成。這份 SQL 使用 `travel_` 前綴，建立旅程、旅伴及邀請資料表，開啟列安全性（RLS），並限制只能由已登入、且有權限的帳號讀取。

請勿關閉 RLS，也不要為 `anon` 或所有登入使用者開放整張表的讀寫權限。網站的資料寫入皆經由檢查登入身分與成員權限的函式。

## 2. 設定登入網址與郵件

在 Authentication 的 URL Configuration 設定：

- Site URL：`https://jerryyang2.github.io/travel-helper/`
- Redirect URLs：加入完全相同的網址。

啟用 Email 登入。App 支援預設的登入連結，也能輸入信件內的 Email OTP 驗證碼。使用登入連結時，請在同一瀏覽器開啟；若要使用驗證碼，需在 Authentication 的登入信範本加入官方的 `{{ .Token }}` 變數。

確認專案的郵件寄送設定。Supabase 內建寄信服務有寄送對象及速率限制；正式邀請旅伴前，應依官方文件完成自己的 SMTP 設定，並用兩個實際帳號測試登入。網站不會代為寄出旅伴邀請，分享連結由使用者自行傳送。

參考：[密碼外登入](https://supabase.com/docs/guides/auth/auth-email-passwordless)、[Email 範本](https://supabase.com/docs/guides/auth/auth-email-templates)、[SMTP 設定](https://supabase.com/docs/guides/auth/auth-smtp)。

## 3. 在 App 連接專案

在專案的 API 設定取得 Project URL 與 **publishable key**，或舊版 **anon key**。在 App 開啟「同步與分享 → 雲端專案設定」填入這兩項公開資料。

不要填入 `secret key`、`service_role`、資料庫密碼、個人存取權杖或私鑰；App 會拒絕管理金鑰。這些機密也不應放進 GitHub、HTML、聊天或備份。

專案連線設定僅保存在此瀏覽器，沒有內建於公開網站。分享連結會包含專案代碼及公開金鑰，讓旅伴在自己的瀏覽器確認連接。公開金鑰不等於登入權杖；真正的存取權仍由登入與資料庫 RLS 控管。[官方金鑰說明](https://supabase.com/docs/guides/getting-started/api-keys)

## 4. 同步與邀請旅伴

1. 以自己的電子郵件登入。
2. 選好要同步的旅程，確認其中的手記、花費、訂位及保險等實用資訊適合讓旅伴查看。
3. 按「將目前旅程加入雲端」。其他本機旅程不會自動上傳。
4. 建立分享連結，選擇「僅供檢視」或「可以共同編輯」，再自行傳給旅伴。
5. 旅伴開啟後，確認專案、登入自己的帳號，再按「加入共用旅程」。自己的手機或電腦也能以相同帳號登入，下載有權存取的旅程。

分享連結有效七天，必須登入才可加入。資料庫只保存邀請 token 的雜湊。撤銷連結會禁止後續加入；已加入的旅伴需要另外移除權限。建立者可在 App 管理旅伴角色及連結。

## 同步行為與衝突

- 連線且頁面可見時，約每八秒檢查更新；編輯結束、離開欄位或關閉編輯視窗後同步。
- 失去網路時先保留本機變更；重新連線後重試。尚未同步的狀態會明確顯示。
- 使用版本號檢查更新，避免直接覆蓋旅伴的內容。不同欄位、不同日期且互不衝突的更新可合併；同欄位或同一組行程的衝突會停止上傳。
- 處理衝突時，先把本機內容另存為獨立旅程，再載入雲端版本。原有編輯可以從「我的旅程」查看或手動整理。
- 檢視者可使用地圖、切換日期、備份，以及複製獨立本機旅程；無法編輯共用資料。
- 登出或移除權限不會自動刪除裝置上已下載的快取或備份。請自行保管共用裝置及匯出檔案。
- 備份只包含旅程資料；不含登入憑證、邀請 token 或雲端同步中繼資料。

## 驗證範圍

資料庫 SQL 已以 PostgreSQL 相容的本機測試驗證 RLS、角色、禁止直接寫入、版本衝突、邀請撤銷/過期及成員移除。前端有本機保存、合併與佇列的檢查。

實際雲端寄信、跨裝置登入及網路延遲，需在建立者自己的已設定專案進行驗收；未設定專案時不會宣稱已啟用同步。

官方參考：[RLS](https://supabase.com/docs/guides/database/postgres/row-level-security)、[資料庫函式](https://supabase.com/docs/guides/database/functions)。官方 SDK 的授權保留於 [THIRD_PARTY_NOTICES.txt](THIRD_PARTY_NOTICES.txt)，單檔 HTML 也內嵌同一份授權。
